The problem

Nobody checks the checker.

Teams watch their AI agents through a dashboard. The dashboard shows whatever the tracing code inside the app writes down. When that code gets it wrong, a crashed run is recorded as SUCCESS, and every chart, alert and report built on it is wrong too.

neatlogs' own daily email
6.2% → 11.1%

The email said 6.2% of runs failed. The real number was 11.1%.

We read all 81 runs back and checked each one. 9 had crashed; 4 of them were never counted. These were test runs we crashed on purpose. The email added up correctly; the records it was given were wrong.

How it works

A second instrument, and a mechanic.

Planes warn pilots when two readings disagree. Trueup gives your agent the same thing, then repairs the faulty reading at its source.

01

Witness watches the real AI traffic

It reads the same connection your app uses to talk to the AI provider, and notes what really came back.

02

Compares it with the neatlogs record

Did the call succeed? Did the run crash? Was the reply recorded? Each reading is checked against the record.

03

Lights DISAGREE inside neatlogs

It writes a red TRACE DISAGREE step into the same record, where a neatlogs detection catches it, ready to raise an alert.

04

Fixes the tracing code

Trueup's agent finds the cause, writes the fix and its tests, proves it, and sends it to the people who maintain that code.

Install

Two lines in your agent.

Witness never changes what your app does, never sends prompt or reply text beyond what neatlogs already records, and turns off with TRUEUP_WITNESS=0.

Read the setup on GitHub → 
import trueup.witness
trueup.witness.watch()

# optional: name one run of your agent
with trueup.witness.run("order-1042"):
    ...
