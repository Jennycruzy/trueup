Task: the truth side.
1. `src/trueup/fake/`: a local HTTP fake provider (stdlib http.server in a thread, or similar; random free port) speaking: OpenAI Chat Completions (plain, streaming with and without usage, tool calls incl. 2 parallel and split streamed arguments, refusal, n=2, HTTP 500, error event mid-stream, dropped connection), OpenAI Responses (plain, function call, reasoning summary, status failed, status incomplete, streaming event sequence, error event, cut), Anthropic Messages (plain, thinking, tool_use with input_json_delta, streaming, error event, cut, 529). Scenario is chosen by the request's model name. Every response id is unique per call. It logs every request and what it sent back (the truth log: number of calls, tokens per call).
2. Fixture tests: each format parsed by the real `openai` and `anthropic` SDKs (add them as dev dependencies) pointed at the fake, asserting the SDK accepts it and the values match. Errors and cuts must raise the SDK's own exceptions.
3. `src/trueup/scenarios/`: the scenario library as data (id, provider/api, framework, what the app does, expected truth fields), starting with the plain-SDK cases (OpenAI chat, OpenAI Responses, Anthropic). Framework cases (LangChain/LangGraph, OpenAI Agents SDK) may be listed but marked not_built if time is short; say so honestly.
4. `src/trueup/runner/`: runs one scenario in a fresh subprocess with a target library's recommended setup, captures every exported span in memory (OpenTelemetry InMemorySpanExporter) plus the app outcome (result or exception type and message), and returns an Observation (truth + trace) as JSON. Per-library venvs under `.trueup/venvs/<lib>` created with uv; libraries: neatlogs (neatlogs.init with its openai/anthropic instrumentation, export disabled), openinference (OpenAIInstrumentor, AnthropicInstrumentor), openllmetry (Traceloop.init with an in-memory exporter, disable_batch=True). Memory is limited: build and run one library at a time. A scenario that can't run is reported NOT RUN with the reason, never skipped.
5. Known traps, each needs a regression test: two scenarios reusing a response id makes a library skip a span; reusing one async client across asyncio.run loops gives "Event loop is closed"; a fake that sends no usage makes missing tokens look like a bug; neatlogs export to a dead endpoint makes a run take 200 s.
6. `trueup sweep <library>` runs the plain-SDK scenarios against one library and writes the observations to `.trueup/runs/<run_id>/` with a short text summary. Comparing truth to trace is the next step, not this one.
7. Add a dated entry to hackathon.md and update CHANGELOG.md. Plain words, no marketing filler.

Run `uv run pytest -q` (keep unit tests offline and fast; mark venv/subprocess tests as e2e) and then actually run `uv run trueup sweep` for each of the three libraries, one at a time. Finish with a summary: tests passed, scenarios run per library, any NOT RUN with reasons.
